# Спецификация

Локальный агент принимает текстовую задачу, отдельно получает план от LLM, затем выполняет её циклом LLM/tool/LLM. Сервис работает с OpenAI-совместимым `chat/completions` (включая DeepSeek) и MCP Streamable HTTP. В явном demo режиме планирование и исполнение детерминированы, а вызовы demo MCP настоящие.

## Критерии приёмки

1. `config.yaml` задаёт верхние `listen`, `database`, `timezone`, `task_timeout`, `mcp_servers` и блок `llm` с `provider`, `service`, `model`, `api_key`, `base_url`, `temperature`, `max_iterations`. Температура по умолчанию 1; явно заданный 0 сохраняется. `${NAME}` берётся из окружения и `--env-file`; отсутствующая переменная даёт ошибку запуска. Переменные окружения имеют приоритет. Секреты отсутствуют в API, UI и логах.
2. При каждой задаче discovery всех настроенных MCP серверов происходит до planning. Недоступный сервер явно проваливает задачу. Planning вызывает LLM без права исполнять инструменты, execution получает план и делает минимум второй LLM вызов. Tool calls обрабатываются до финального ответа, с ограничением итераций, таймаутом и отменой.
3. Агенту доступны встроенные инструменты создания, просмотра и отмены расписаний. Расписание хранит самодостаточный текст будущей задачи и либо пятичастный cron с IANA зоной, либо `run_at` RFC3339. При наступлении запуска создаётся новая Task, выполняющая полный цикл MCP discovery → planning LLM → execution LLM/tool. При просьбе о будущем действии агент планирует расписание, не выполняя целевые действия заранее.
4. Задачи, события, расписания и запуски сохраняются в SQLite. Каждый Run связан с Task. Просроченный one-shot после рестарта выполняется. Для recurring расписаний пропущенные моменты объединяются: исполняется один запуск, затем `next_run_at` переносится на следующий момент после текущего времени. Одно расписание не исполняется параллельно.
5. После падения процесс не повторяет автоматически уже начатую задачу: незавершённые запуски помечаются `interrupted`, расписание с неопределённым исходом выключается и требует решения человека. Гарантии exactly-once для внешних действий нет.
6. HTTP API соответствует `docs/api.md`; адрес по умолчанию `127.0.0.1:8080`. Запись требует JSON и same-origin проверку. Frontend отдаётся из `frontend/dist`, если он существует. Развёртывание предполагает доверенную локальную машину.

MCP Tasks — стандарт асинхронного получения результата задачи, но не формат cron-расписаний: https://tasks.extensions.modelcontextprotocol.io/specification/draft/tasks . Локальное расписание — функция этого приложения.
