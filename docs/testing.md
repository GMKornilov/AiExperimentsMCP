# Проверка

Запуск из корня проекта:

```sh
go test -race ./...
go vet ./...
```

На 27 сентября 2026 обе команды завершились успешно. Для `go test -race ./...`: `cmd/agent` и `cmd/demo-mcp` собраны, в `internal/app` тесты прошли без race detector ошибок. `go vet ./...` завершился без диагностик.

Интеграционные тесты используют локальный `httptest` для OpenAI-совместимого HTTP endpoint и MCP Streamable HTTP сервер на официальном Go SDK; внешние API и платные ключи не вызываются. Проверены:

- YAML конфигурация: температура по умолчанию и явный ноль, приоритет окружения над `.env`, отсутствие переменной, спецсимволы и переносы в секрете без внедрения YAML.
- Задача: отдельный planning HTTP запрос без инструментов, исполнение с инструментами, передача MCP результата и `IsError` следующему LLM запросу, ограничение итераций и отмена ожидающего HTTP запроса.
- Логирование вызовов: JSON-записи начала и завершения LLM/MCP с `task_id`, стадией и общим `call_id`; initialize/list/call и `IsError`, HTTP/MCP ошибки, отмена, невалидный ответ LLM, ограничение размера payload и сокрытие ключей, Bearer credential, вложенных и экранированных JSON-секретов.
- API: отсутствие секретов в `/api/config`, требования JSON и same-origin, проверка расписаний с неверным cron, зоной, отсутствующим prompt или одновременно cron и `run_at`.
- Расписание: новая задача после срока проходит повторный planning и execution с зоной расписания; MCP действие не происходит до срока. Просроченный one-shot выполняется после рестарта. Cron и зона сохраняются в SQLite. Атомарный claim создаёт один Run и Task, а начатый и незавершённый Run после рестарта получает `interrupted` без автоматического повтора.

Ограничения проверки: не выполнялись реальные LLM или MCP сервисы, внешняя доставка сообщений и длительное ожидание cron по реальному календарю. Повтор cron после фактического запуска и объединение нескольких пропущенных интервалов отдельно не проверялись.

## Браузерный smoke

Все четыре сценария прошли: создание задачи с планом, результатом `get_time` и выключенной отправкой пустой формы; список инструментов `echo`/`get_time`; one-shot расписание с завершённым Run и переходом к связанной Task; три страницы на экране 390×844 без горизонтального переполнения.
